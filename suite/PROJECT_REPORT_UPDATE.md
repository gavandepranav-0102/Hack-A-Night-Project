# BuildProof — Cost / Planning PDF report update

This is the original integrated BuildProof suite with **only the auditor PDF renderer changed** and one isolated new PDF rendering module/test added. The existing signup/login and role rules are unchanged.

## Report layout (matches the supplied drawing)

1. Report title in a black/yellow header.
2. Two vertical columns: **Cost / Storekeeper** (submitted invoices, values entered by storekeeper, previews) and **Planning / Supervisor** (site and stock photo evidence, submission flags, limitations).
3. Below the columns: **Cost bar chart** (entered quantity × entered rate, where available), **Planning bar chart** (counts of site photos, stock photos, and flagged site photos).
4. Copyright/confidentiality footer and page numbers.
5. Evidence appendix with previews of **all** uploaded supervisor photos and storekeeper invoice images / first pages of PDFs.

The report is generated by a **Python FastAPI REST endpoint** and returned as an attachment with a `.pdf` filename. Only authenticated Project Auditors can fetch it.

## How to generate

1. Start PostgreSQL and ensure `suite/backend/.env` is configured. Do **not** share this file.
2. Terminal A from `suite/backend`:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000 --env-file .env
```

3. Terminal B from `suite`:

```powershell
npm run all
```

4. Sign in as an authorized **Project Auditor**, open the auditor dashboard, and use the existing **Analyze Automatically** control. It performs `POST /api/workflow/auditor/analyze` then downloads `GET /api/workflow/auditor/reports/{run_id}.pdf`.

## Important limits

- A photo **cannot** establish precise stock quantity or a verified percentage of construction completion. Graphs show recorded amounts or upload counts, NOT invented site measurement.
- The **cost chart** uses storekeeper-entered invoice quantity and rate; where rate is missing, the value is unavailable. It is not an independent financial estimate.
- AI authenticity classification requires the optional configured image detector. Missing AI data is marked `NOT_EVALUATED`, not `REAL`.
- The planning chart presents submitted evidence counts; implementing verified work-completion percentages requires real milestones, stage checklists, human verification and/or dedicated VLM integration.
- Rendered PDF files are only generated on demand; the REST API maintains existing authorization requirements.

## Test

From `suite/backend`:

```powershell
python -m pytest tests/test_project_report.py -q
```

All PDF content stays inside the existing Project Auditor role workflow.
